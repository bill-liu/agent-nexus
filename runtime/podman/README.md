# Podman accountless candidate

Implementation candidate: Podman client/server **6.1.4**, upstream source **464c15fec06f0074c916f9eff87c4806869c2833**. See the [migration slice](../../docs/plans/podman-first-slice.md). This directory has no image digest because **no image has been built, downloaded, run or published**. Do not invent a release digest or use `latest`.

The trusted Core adapter is `createPodmanEnvironmentAdapter`: an existing Core DB/provision identity, explicit engine target, synchronous current-owner and action authorization, plus a pinned process transport. Normal desktop admission still rejects live operations by default. The old VM admission package is not Podman authorization. The generic Provider seam does not make the old cgroup/BPF runtime attestation valid for Podman; the first accountless endpoint offers no such attestation, login or task/model methods.

For a later explicitly authorized **private local build**, first qualify an official `node:24.19.0-bookworm-slim` Linux/arm64 base manifest digest and Codex 0.159.2 Linux/arm64 executable digest/provenance/license. CLI installation and public redistribution are separate reviews. Run `npm run build` to bundle the existing channel/Runner/Codex Driver into `build/podman-entry.cjs`. Prepare an empty private build context containing this Containerfile and its allow-list `.containerignore`, that public bundle, the reviewed public `codex` executable and `runtime.json` (`{"version":"0.159.2","sha256":"<verified executable SHA256>"}`). Do not copy a checkout, home, `.env`, login cache, project data or keys. Build with immutable BASE_IMAGE, IMAGE_VERSION and SOURCE_REVISION arguments; record the resulting **single-platform OCI manifest digest**, base/CLI provenance, complete input hashes and target results before configuring a PodmanTarget. No build command is wired to startup or CI.

The runtime contract validates OCI version, source revision, protocol, Codex version, Linux/arm64 and immutable fully qualified digest. Provider only uses an already-present image (`--pull=never`); downloading/publishing is not implemented in this slice. A caller must not silently fill a missing digest. Named local volumes belong separately to each Bot: `/an/work` for business work and `/an/private` for private state/probe homes. The latter must be excluded from ordinary backups. Neither volume is removed on task completion, stop or container retirement. Both live inside the selected Machine, and Machine reset/delete can destroy them: volumes are not backups.

Every engine operation uses a pinned URI/SSH identity, after verifying the explicitly selected named connection and Machine. It never changes the global default. This candidate requires an already-running rootless Machine with **zero host shares** and a protected config matching machine name/SSH endpoint; existing default Home shares block it. No automatic machine modification, start, stop or conflict resolution. Machine inspect does not expose shares in 6.1.4; its named version-1 config is checked separately. No engine socket, host bind, published port or management credential enters Bot containers.

Accountless exec receives an ephemeral channel key over stdin and only initializes the pinned Codex app-server protocol. Fresh probe homes are separate from any Bot login state. It cannot start turns or login. The CLI parent/exec pipe closing never proves the process tree stopped. The trusted Core adapter stops **only the exact owning Bot container** and requires fresh owned-container/PID/exec readback before clearing its durable sole-writer claim. The local exec client must also be confirmed closed; losing that client handle across a Core restart blocks automatic release. A lost stop reply, foreign binding, unknown readback or failed authorization keeps that claim. This fallback ends all sessions in that Bot container; it does not stop the shared Machine or other Bots. Precise per-Run native stop and live descendant-negative tests remain to qualify before general task reuse.

No accounts, models, costs, credentials or public image distribution were exercised. Real Mac installation/Machine resources/OCI acquisition and start require a new named Podman scope. Original Task A/B additionally require named Connection/data/billing authorization and actual network/gateway controls; network:none does not implement domain/request policy. Mac app/JSC independent verification remains on macOS.

Preserve Podman's resulting single-platform manifest digest and all provenance. This slice supplies no automatic image build/pull/Machine/installer command; missing engine facts stay blocked. The minimal Node+Codex candidate is not a general project build environment; no package manager/network/tool installation is implicitly granted.

A Bot version change still stops new preparation effects. Only the currently live original controller may reconcile/stop its original owned container within the original cleanup deadline, preserving Core epoch, Bot generation, provision fence and frozen execution binding. This does not adopt a restarted/replacement owner. Unknown stop/PID/exec/client delivery keeps the durable writer; the shared Machine and other Bots remain outside this cleanup scope. A reconciled stopped container does not turn an uncertain start delivery into a completed initialization.
