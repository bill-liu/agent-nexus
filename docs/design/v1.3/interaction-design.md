# Agent Nexus 2.0：界面与交互详细设计

版本：UX v1.3 · Electron / Mac-first / Desktop + Resource Server  
日期：2026-10-12  
配套基线：[产品与技术设计 v1.3](technical-design.md)。本文为待实施和验收的交互规格，不是已实现界面、在线原型或实测结果。

本文完整替代旧版交互实施基线，保留长期 Bot、动态目标、持续交互、独立验收、成长、Mac 桌面体验，新增资源下载、知识/Skill/规约和连接授权全流程。示例 Bot、目标、版本、时间和数字均为演示。

> 用户把事情交出去，随时继续沟通，在必要时作出明确决定，拿到有证据的结果，并看到经验在下一次工作中被用上。

## 01. 产品范围与交互原则

一期仅交付 Mac Electron App。React 实现业务界面，Electron Main 接入窗口、菜单、系统文件面板、通知和授权桥。不要求 SwiftUI 主界面，不以浏览器管理网站作为主产品，也不预建手机/平板、Windows/Linux 客户端或跨端同步。

主导航固定为任务指挥台、Bots、成长。项目、资源、连接、节点、权限在设置或上下文入口中；不增加员工/部门/固定 Workflow 管理。AN Resource Server 是配套环境与公共资源服务，不成为第四个工作入口。

信息优先级：需要用户处理的问题、当前可确认状态、接下来会发生什么、交付证据、完整记录。原始模型输出不是权威系统状态；不展示无依据的完成百分比、剩余时间、专家评分或成长增幅。

任务详情以事情为中心，Bot 工作台以长期合作为中心。两者引用同一 Task/Conversation/Artifact，不复制两套不一致的消息和进度。任务完成不销毁 Bot 或 Sandbox。

### 2.3 导航与恢复

返回保留筛选和阅读位置；从 Goal 点 Bot 要定位该 Goal 相关对话，从经验点来源要定位原任务事件。深链接只定位已授权对象，不能自动批准、执行或删除。未知对象、无权限和记录被归档有不同错误页面。

Renderer 重载、关闭详情、重开窗口都不能再次提交工作；未确认请求继续查询原 command_id。窗口内表单可以保存普通草稿，但 API Key、验证码、OAuth 信息不进入草稿。

## 03. S00 首次启用

首次路径：打开 App → 选择项目与数据位置 → 准备本机隔离环境或连接远程节点 → 选择受测 Runtime 与连接 → 绑定必要资料/Skill/规约 → 创建第一个 Bot → 一项小工作 → 查看交付。

默认突出“在这台 Mac 上执行”，远程执行并列可选。准备 VM 前显示执行架构、来源、需下载内容和存储/资源需求；用户确认后再下载。没有资源目录连接时，允许使用已有经过验证的缓存或授权远程环境，不能把资源目录故障伪装成整个 App 不可用。

用户不需要先部署数据库、Node/npm 或 Web 后端。公共资源服务器登录不是所有本地功能的前置；私有目录、特定服务或模型使用自己的授权。说明“App 数据本地保存”和“任务可能把材料发送给所选模型”是两件事。

每个阶段保留进度，失败只重试该阶段，不重复创建身份或重新下载完成部分。不要求一次配好所有 CLI、四个 Bot 或全部云服务。首个 Bot 的环境就绪但未登录时进入“等待授权”，不删除已建立环境。

## 04. S01 任务指挥台

默认展示需要我处理、正在推进、待验收/最近交付。没有需处理项则收起，不用大面积零指标占位。

```text
任务指挥台                         [交一件事]
项目：全部▾  状态：活跃▾   搜索工作…

需要你处理
暂停派工功能 · 所选连接需要重新授权
Bot：开发 Bot    环境：远程节点
已有代码已保存；不会自动改用 API 计费
[处理连接] [查看工作]

正在推进
为 AN 增加暂停派工功能        负责人：研发调度
当前：修复独立测试发现的并发问题
验收：2/4 项已验证，旧候选证据已失效
[查看进展] [补充要求]

最近交付
导出字段调整 · 可合并，未合并  [查看成果]
```

卡片显示目标、负责人、当前动作、阻塞、最新有效进展、验收事实和最后确认时间。点击验收定位具体条件，点击 Bot 名称保留来源 Goal。不同筛选的空结果与从未创建工作的空页面分开。

连接失联显示“状态尚未同步·最后确认……”，不以旋转指示器宣称模型仍在推理。资源下载、等待授权、排队和模型运行不是同一状态。模型对话摘要有时间与来源，不能覆盖系统事实。

## 05. S02 交一件事

四项主要信息：想做成什么、交给谁、项目/资料、做到什么程度算完成。高级折叠权限、费用/预算、停止条件与本次连接覆盖。

```text
交一件事
目标        [为 AN 增加暂停派工，达到可合并状态……]
负责人      [自动安排 · 研发调度 ▾]
项目/资料   [Agent Nexus ▾] [附加资料]
完成标准    [AI 帮我补全] / 自行编辑
当前连接    使用各参与 Bot 已批准的默认连接 [查看]
高级设置▸   权限、预算、停止条件、本次连接

可执行：授权项目分支读写与测试
不允许：合并主分支、生产发布
[保存草稿]                              [提交工作]
```

从指定 Bot 发起时默认该 Bot，简单任务不经调度 Bot。自动安排必须显示真实负责人。AI 补全只在明确操作时执行，建议可编辑，不要求人逐项拆任务。

提交前可展开生效的资料范围、规约、Skill、连接和数据处理位置。复杂 Goal 可能委派多个 Bot；预算/连接政策是整个 Goal 的约束，不把负责人一个账号假装为全部成员的计费来源。用户指定 Goal 连接限制后，下游不兼容必须阻塞或请求明确更改，不能默默换身份。

目标基本明确可直接提交；缺少安全执行所必需的验收/权限时先澄清。提交后显示平台已受理，再由持久化与派工事件展示排队/准备/执行。请求超时先查询原 operation，不产生第二件工作。

任务级覆盖默认关闭。用户选择其他连接前展示账号/组织、认证方式、计费来源、端点、资料流向及是否符合项目规约。切换只是申请，Core 仍需验证；不能因 UI 成功选中就绕过授权。

## 06. S03 工作详情

页头显示目标、负责人、当前状态和常用动作“补充要求”；更多菜单为暂停后续派工、取消、导出。主体四个标签：进展、执行计划、成果与验收、记录。

```text
‹ 指挥台    为 AN 增加暂停派工功能
研发调度 · 处理中          [补充要求] [更多]
进展 | 执行计划 | 成果与验收 | 记录

当前：开发 Bot 修复事务边界       验收标准 v2
依据：独立并发测试反例             2/4 已验证
下一步：验证同一候选版本           [看证据]

计划调整 #2 [展开]                 参与 Bots
新增设计修订与并发回归             设计 / 开发 / 评审
旧候选 C1 证据不计入当前验收

相关资源/连接 [查看本轮快照]
```

进展只呈现关键决策、里程碑、阻塞与结果。读取文件、工具命令和 token 流折叠到记录。专业 Bot 详细对话在其工作台，Goal 视图引用有关结果，不成为无限群聊。

改变验收、项目或授权会生成契约差异、影响任务和旧证据清单；普通补充只交给明确的 Run/负责人。原 Goal 已成功时，新增要求默认创建关联后续工作；重开原 Goal 需显式修订，保留历史成功结论。

## 07. 执行计划与真实重规划

默认列表显示任务、负责人、依赖、状态和服务的验收项；依赖图只读按需展示，不是拖线配置 Workflow。图位置变化不改变任务，不能手拖到成功列。

重规划必须展示触发证据、旧假设、具体变化、影响范围及是否需新增授权。示例：独立测试发现暂停与领取竞态 → 新增事务边界设计及回归 → C1 验收过期 → 负责人委派修复。

历史被替代节点可折叠不可抹除。当前图版本与历史查看明显区分，比较用“新增/替代/输入过期”等文字，不只靠颜色。换 Bot 涉及活动执行时，先确认停止或等待安全边界，不能立刻换头像假装已接手。

允许用户提出调整、建议换 Bot、补充限制；正常授权范围内调度无需每步确认。权限、费用或资料流向变化才进入审批。更多重规划次数不是更聪明的评分。

## 08. 成果、证据与交付

首屏显示交付摘要、candidate_digest、验收契约版本、必需项结论与限制。代码任务有 diff、测试、评审、复现；文档任务有正文和原件。

Bot 自测、独立验证、人工/语义评审使用不同来源标识。每份报告绑定确切版本；代码更新使旧证据过期，不能用过去 PASS 宣布新候选完成。缺少测试或报告无法访问时显示实际缺口，不用人工“确认完成”按钮掩盖机器门禁失败。

可合并、已合并、已部署分开。创建 PR、合并、发布权限分开；未连接对应工具不提供假按钮。完成后“继续追加”默认新工作并附当前交付版本，不创建新 Bot 或清空工作环境。

## 09. S04 Bots 列表

卡片显示名称、职责摘要、可用状态、当前工作、排队数量、运行位置与必要的授权提示。排序稳定，状态变化不使准备点击的卡片突然移动。可收藏/筛选，不默认以绩效或角色等级排序。

| 文案 | 实际意义 |
|---|---|
| 在线空闲 | Runner 可达、无主动写任务、所需连接可用 |
| 执行中·排队 N | 有活动工作，其他已接收任务在 Inbox |
| 等待输入/子任务结果 | 等待明确前提，并非不断推理 |
| 环境就绪·待授权 | 身份/磁盘/Runner 已准备，所选连接未可用 |
| 后续派工已暂停 | 可继续收单，当前任务可继续 |
| 暂停接收新工作 | 不接新提交，既有任务仍按原策略 |
| 休眠/已停止 | 身份和数据保留，按策略可唤醒 |
| 状态未知 | 无法确认远端执行，不能强制重跑 |
| 维护/授权受限 | 明确缺失兼容性、许可或版本要求 |

Orchestrator 使用同一类卡片，只是职责不同。新 Bot 显示未有验证记录，不能预填“专家 98 分”。更多菜单包含接单/派工开关、环境、归档；永久删除在危险操作区。

## 10. S05 Bot 工作台

左侧项目/对话、中间当前对话、右侧可收起的当前工作 Inspector。主导航与会话列表避免重复占据过多宽度。顶部一直显示 Bot、项目与关联 Task。

```text
开发 Bot · 执行中          [交新工作] [更多]
对话 | 队列 | 工作区 | 环境 | 能力与资料

项目 / 会话          暂停派工 · Task T42       当前工作
AN                   你：补恢复后验证         候选 C2
  暂停派工           系统：已排队              验收 2/4
  并发限制           Bot：……                   Diff/测试
                     [变更卡]                  本轮连接
                     [经验采用卡]              本轮资料
                     ──────────────            [展开]
                     补充当前工作 ▾
                     输入…… [发送]
```

相同 Bot 可以有多个对话和原生 Session。新会话不新建 Bot；新 Task 可建立新分支/会话而不丢身份、工作材料和已验证经验。上下文不明确时选具体候选，不能恢复全局“最后一次 CLI 会话”。

系统状态卡和模型文字分开，模型输出“已授权”“已完成”不能伪装成平台事实。记录卡引用 Artifact/Approval/Memory，避免复制大段日志。所有草稿按 Bot/Conversation/Task/窗口保存，切换不串发。

## 11. 输入、插话与控制

输入意图：补充当前任务、交新工作、讨论、作为长期偏好。自动识别只给建议，标签可见可改。讨论不获得改文件授权，若需动手转工作；长期偏好先选适用范围。

```text
发送中 → 平台已接收 → 排队 / 已交付运行时
                              → 已应用 / 被拒绝 / 无法确认
```

收到/回复都不自动证明要求已采用。活动补充绑定 expected_turn_id，迟到时不进入下一件工作；允许用户改为后续任务或重新绑定。Runtime 不支持 steer 时，发送前明确本轮结束后交付或用户确认的中断续接。

| 操作 | 语义 |
|---|---|
| 暂停接收新工作 | 拒绝新的工作提交，不影响既有任务 |
| 暂停后续派工 | 当前工作继续，等待任务不启动 |
| 中断当前执行 | 停当前轮次，任务/成果保留等待检查 |
| 取消当前工作 | 不继续该工作；不承诺回滚已发生外部动作 |
| 接管工作区 | 确认 AI 停写后取得独占控制 |

取消/中断请求有“正在停止”，未确认前不可显示已停止或释放写控制。不能因为用户连点重发而创建第二次操作。查看进度不抢写槽位，新讨论需要模型运行时可以明确排队。

## 12. S06 Inbox 与队列

分当前执行、待执行、等待条件、已完成。显示来源、项目、优先级、进入时间、依赖或授权阻塞；队列编号只表示目前顺序，不承诺开始时间。

默认提供提高/降低优先级而非只支持拖拽；优先级不越过依赖、费用或权限。新任务要立即做时，提供等待当前完成或先中断当前，不并发改同一工作区。

来自 Goal 的 Task 被取消/换人应反馈负责人，保留历史。暂停派工确认前已领取的 Run 清楚标“准备/执行中”，不能伪装成系统违约。队列版本冲突后刷新保留用户编辑。空队列显示“Bot 仍在，可以继续交工作”。

## 13. S07 工作区与接管

默认只读文件、diff、测试与终端日志。始终显示项目、Goal、分支和候选版本。敏感或未授权文件不显示名称或搜索片段；产物 HTML/SVG 无脚本、无自动外链，不加载主业务桥。

```text
申请接管 → 停止 AI 写入 → 确认退出/写锁
→ 人工接管 → 保存变更事实 → 交回 Bot
→ Bot 重新观察 HEAD/文件/材料 → 检查失效证据 → 可继续
```

旧节点失联、状态未知时禁止强制接管同一写工作区。接管期间常驻状态条，关闭窗口/超时不自动授权 Bot 恢复写入。用户交回时可补说明；没有说明也比较实际文件，不能假装人没改过。

日志分页/虚拟化，用户选字或向上阅读时停止自动跟随，新增内容给可点击计数。大文件下载/打开失败保留当前上下文并说明访问或材料失效原因。

## 14. S09 创建 Bot 与 S08 环境

### 14.1 创建向导

采用四步，可返回并保存非秘密草稿：

1. 职责与模板：名称、负责什么、可选种子 Bot，模板来源与版本。
2. 执行环境：本机/远程节点，所需环境模板、资源、已有缓存和缺失下载。
3. Runtime 与连接：受测 CLI、具名连接、计费来源、请求路径、允许节点；未授权可稍后完成。
4. 资料与权限：绑定项目知识/Skill/规约，检查有效授权与冲突后创建。

必填仍尽量少；默认必须显示，不以“高级设置”隐藏使用哪个账号、会不会产生 API 费用。公共模板不是训练好的专家；创建多个 Bot 不等于获得多份订阅。

### 14.2 分段就绪

异步状态按 Bot 记录创建、下载/校验、持久环境、Runner/CLI、资料装载、连接授权分开。成功阶段保留，失败修复原 operation。Bot 可以“环境就绪、等待授权”，不因未登录清空环境。

环境卡展示期望/观察状态、最后心跳、持久数据、Runtime/版本、模板、连接摘要、实际能力、资源及维护动作。重要事项包括“此环境尚未登录”“凭据方式与选择不符”“需要升级”“本地网关不可达”。不要只有一个总体绿色在线。

### 14.3 维护

停止保留身份和数据；升级前排空/检查点，列出只改基础环境还是涉及数据迁移。切 Runtime 提醒新原生会话；迁移提醒认证可能需重新完成，不把旧登录文件普遍打包传走。

普通任务结束不出现销毁动作。归档与永久数据清除分开，后者列范围/备份/不可逆限制并明确确认。模板撤回是停止新安装及告知风险，不在后台删除现有 Bot。

## 15. S15 项目知识与规约

### 15.1 资料管理

项目设置提供资料、规约、已绑定 Bot、数据处理政策。资料页支持文件/目录/仓库材料导入、来源预览、状态、版本、更新、撤回和权限。

```text
项目：AN      资料 | 规约 | 数据使用
[添加文件] [添加目录] [绑定已有资料]

资料                 来源版本       状态       可访问 Bot
产品设计             v1.3/hash…      已索引     设计/开发/评审
接口规范             hash…          待更新     开发/评审
领域资料             hash…          仅本地     领域 Bot
```

导入前显示实际路径/项目/上传去向/是否云模型可处理。目录变化先发现新版本，再明确应用；不把“索引完成”写成“Bot 已学习”。删除资料与撤销绑定不同；撤销后列出已装载的活动 Run，说明不能自动让模型遗忘已读内容。

一期关键词和结构化筛选即可，语义检索后加；无向量库不阻止使用。无法解析的文件显示原件可用与索引限制，不伪造全文检索。私有文件不自动发布公共目录。

### 15.2 数据使用政策

显示“保存在本机”和“允许谁处理”两行。可选仅本地处理、允许指定供应商/网关、指定远程节点。约束覆盖检索、Embedding、摘要、工具与推理，不能仅最后一步检查。

连接变更导致资料离开获准范围时，提前拦截。用户可请求改变政策，但不能通过改 Bot 默认连接静默扩大整个项目授权。

### 15.3 规约编辑与生效预览

规约分行为指导与硬权限，编辑页必须标类型、作用域、来源、版本、生效时间。提供“查看最终生效规则”，展示继承、收紧、冲突和实际执行点。

例如项目禁止合并主分支，Bot 规则不能覆盖允许；相互矛盾的格式/架构要求返回冲突并说明源文件。硬权限有 Kernel/挂载/网络/工具网关等执行方式，单纯写到 Prompt 不显示为“强制防护已启用”。

发布影响标为新任务生效、下一轮生效或立即撤权。活动 Run 使用固定版本，但硬撤权触发真实执行限制；不能以“固定快照”拒绝必要撤权，也不能说旧上下文已消失。生成 CLI 指令文件前展示差异并保留用户已有内容。

## 16. S16 资源库与 Skill

设置内分“已安装”“公共目录”“自定义”。同一资源可在多个 Bot 绑定，但无需反复上传。公共目录有发布者、版本、内容摘要、兼容 Runtime、下载大小、需要的权限、源码/脚本与验证信息；过期或撤回状态明确。

Skill 操作流程：查看说明/脚本/权限 → 安装固定版本 → 选择项目/Bot 启用 → 检查已有授权 → 后续任务采用。安装、启用、授予权限分别记录，不能一个按钮顺带批准生产动作。

有脚本显示“可执行内容，需要审查”；审查或签名不能标为绝对安全。Skill 在 Sandbox 中执行，不成为 Electron 插件。更新版本显示差异、受影响 Bot/任务、兼容性和后续生效范围，活动 Run 不自动热换。

Bot 的“能力与资料”页显示知识绑定、启用 Skill、生效规约、经验引用和默认连接入口。成熟的学习产物可以从成长发布为版本化私有 Skill；共享到 Server 必须另外确认并检查秘密/许可。

## 17. S17 连接与授权

### 17.1 用户选择连接，不选择临时凭据拼装

```text
连接与授权                           [添加连接]
名称               身份/计费来源          路径       状态
个人 Codex         已选择的 ChatGPT 账号   官方       部分环境待登录
公司 API           公司 API 账户           网关       可用
本地模型           本地服务                本地端点   待验证

选中连接：个人 Codex
认证方式：官方运行时登录（受测/获准能力）
计费来源：按连接及运行时报告展示；缺失则标来源/未知
允许：项目 AN、开发 Bot、指定节点
默认备用策略：询问我，不自动换 API
[查看使用者] [重新验证] [修改授权范围] [撤销]
```

认证方式、计费来源、请求路径各自一栏。不能把所有浏览器登录标订阅，也不能把所有 API Key 标为同一家模型的计费。只显示真实已验证或用户声明的账号信息，并标证据来源。

列表状态包括可用、部分环境待授权、已过期、额度受限、不可达、方式不匹配、策略限制、已撤销、未知。Connection 跨 Bot 复用不意味着环境登录状态相同；详情按 Bot/节点/Runtime 显示 AuthSession。

### 17.2 添加连接

选择 Runtime/提供商 → 选择当前获准认证方式 → 填写非秘密名称/端点/账号用途 → 安全输入 API Key 或在目标环境走官方授权 → 测试兼容性 → 选择项目/Bot/节点范围 → 保存。

保存 Key 通过专用受限接口进入安全存储；普通页面只显示掩码与状态，不支持把已保存明文重新复制到任意 Bot 聊天。测试调用可能有费用，发生真实调用前说明；仅本地格式校验不得写成已验证上游计费。

对网关说明谁运营、资料经过哪里、上游账号/Key 谁持有、可用模型和限制。变更端点需重新校验/确认，不把“同名连接”用于替换成第三方地址。共享已登录账号的多个 Bot 明示共享上游限制，不承诺独立额度。

### 17.3 官方能力与许可

所有登录入口按 Runtime 能力与厂商许可启用。Codex/其他受支持驱动可以在实际环境发起官方设备/浏览器流程；远端没有浏览器不自动改为 API。

Claude Code 产品集成必须遵守当前厂商第三方认证限制。未有适用许可时，AN 内的订阅登录路径显示 POLICY_RESTRICTED，并提供获准 API/网关连接，而非用“官方 CLI 装在沙箱”当作许可证明。用户不得通过一个“我承担风险”勾选绕过明确的供应商限制。具体理由与官方参考在技术设计第18章；不要把保守发布门禁描述成技术上无法运行。

## 18. S18 在目标环境完成官方授权

授权页由可信用户操作发起，绑定 flow_id、Bot、节点代际、Runtime 和连接版本。页面显示实际目标，而不是模糊“登录成功”。

```text
为开发 Bot 完成授权
运行环境：远程节点 / 当前 Sandbox
运行时：Codex CLI（受测版本）
使用连接：个人 Codex

1. 在官方网页完成账号确认 [打开官方授权页]
2. 按官方流程输入临时设备码（如该流程需要）
3. 等待目标环境验证

[取消此授权]                    状态：等待官方回执
```

打开系统浏览器只允许 AuthAdapter 认可的地址；普通 Bot 输出的 URL 不作为系统授权链接。设备码/验证码/临时回调信息仅用于此流程，不进入会话、通知、剪贴板自动历史或遥测；复制由用户主动执行并提示敏感性。

关闭面板可以继续显示进行中的授权操作，但只有受支持流程和有效期内才等待；明确取消则标取消、拒绝迟到回调。超时后重新发起新 flow，不把旧码绑定到另一个 Bot。成功后必须检查目标环境的实际认证/账号/权限，浏览器页面显示完成本身不是 AN 的最终就绪证据。

授权有效则可复用，不每个任务重新登录。失效时保留 Sandbox 和任务，给重新授权入口。不读取并复制宿主机全部官方登录文件，不提供上传订阅 Token 到公共 AN Server 的 UI。

## 19. S20 执行前连接解析与切换

### 19.1 只读预览

每次 Run 显示冻结的有效连接摘要、所用 Runtime/模型、认证方式、费用来源及出处、批准端点、项目政策和上下文版本。高级展开可看 Grant/连接版本，但无原始 Key/Token。

启动前 Core 做确定性解析：Task 显式覆盖或 Bot 默认 → 权限/数据/节点/兼容性 → 清理冲突凭据 → 实际认证检查 → 固定快照 → 启动。UI 选择只是意图，不能覆盖实际结果。

| 错误 | 页面说明与下一步 |
|---|---|
| AUTH_REQUIRED/EXPIRED | 环境和工作保留，需要在此环境授权 |
| AUTH_MODE_MISMATCH | 所选账号方式与运行时生效方式不符，未启动 |
| GATEWAY_UNAVAILABLE | 暂停等待网关，不绕过直连 |
| CONNECTION_INCOMPATIBLE | 当前 CLI/模型/节点不支持该连接，选择受测配置 |
| POLICY_RESTRICTED | 项目/厂商策略不允许该路径，说明依据 |
| ACCOUNT/USAGE_UNKNOWN | 无法确认所需来源，需验证而非猜测 |

### 19.2 默认不跨费用来源自动切换

订阅额度不足/登录失效时，不静默改 API；API 失败不借其他账号；网关失败不绕过直连。通知写清“没有产生新的替代来源调用”。已经发出的请求是否扣费无法确认时显示未知，不能宣称绝对未花钱。

申请备用连接时展示旧连接、新连接、计费/数据差异、限额、影响 Task、现有 Run 是否停止，以及旧副作用有无未知。用户批准后在安全边界建立新的 Run/会话；不能为了换认证把整项任务重复执行。

预先允许自动备用是高级设置，必须具名连接、项目范围、触发原因、有效期、费用与数据条件。默认关闭；撤销预授权后不再使用旧规则。

### 19.3 撤权

撤销 ConnectionGrant 先列出受影响 Bot/任务/租约。禁止新用量、处理活动执行并记录未能撤回的已发送请求。原始直连 Key 的风险说明为“AN 已停止新授权，不代表上游 Key 自动失效”，必要时指向上游轮换操作。不能用“已撤销”误导用户秘密泄露已完全解决。

## 20. S19 下载、版本与环境维护

下载列表按资源而非 Bot 聊天展示：模板/组件名称、版本、来源、目标节点、阶段、已下载/总量（已知才显示）、验证结果和关联 Bot。

阶段为解析清单、等待确认、下载、校验、安装、验证、就绪；未知大小显示字节累计，不伪造百分比。请求过期重新申请下载授权；取消下载不取消无关任务或清掉已使用缓存。

Mac 端只是查看远程节点下载进度，远程可直接取制品，不强迫全经 Mac 中转。不同架构选择不同包，源版本不兼容显示阻止原因。包签名、摘要或解压路径不合规时拒绝激活，不能“仍然安装”绕过必需门禁。

资源服务不可达：提示新下载/更新暂不可用，已装环境按执行与授权实际状态运行。环境目录状态与模型网关状态分开，避免用户以为一个服务器故障导致所有组件不可用。

升级详情区分 App、VM/基础环境、Runner/CLI、Skill/Harness。显示当前/目标版本、兼容性、受影响 Bot、是否需要排空、数据迁移及恢复限制。新模板不强制重建在线 Bot。撤回版本提示暂停新安装与维护建议，不在后台销毁长期环境。

## 21. S10—S12 可验证的成长

成长仍分经验、技能、策略、版本，带项目/Bot 过滤。默认展示待确认、已采用或需撤回处理的变化，不显示“等级+1”。

经验详情有内容、成立条件、不适用范围、技术/项目版本、来源任务/人工纠正、确认者、采用记录。操作为确认发布、修订后发布、拒绝、撤回；默认范围不扩大到整个团队。单次成功标为案例，不宣称泛化。

采用回执区分检索到、已装上下文、声明采用、结果关联、经过对照验证；不是自动升级关系。来源 Goal A→新 Task B 采用→B 验证通过能证明复用，不自动证明节省一定时间。

版本比较展示改动、样本、测试集、失败明细、费用来源与退步。关键回归失败不可发布；新版本仅新 Run 使用，活动 Run 不热换。回滚工作策略不回滚历史代码或外部行为。

P5 决策策略显示仅观察建议、小范围生效、已生效、回退，说明优化 AN 外层哪个决策。未实现不出现“立即自进化”。决策模型不能自动改 Connection、计费或权限；失败只退到获准基线，而非扩大账号选择。

## 22. S13 审批、澄清与人工验收

澄清回答缺失事实，审批授予准确操作，人工验收作结果判断，三者不可混用。“已读”不等于批准。审批展示动作、资源、参数摘要、候选版本、用途、风险、费用/资料流向、次数和有效期。

批准创建 PR不等于合并发布，批准连接测试不等于永久借给全部 Bot，批准安装 Skill不等于提升生产权限。参数/候选/目标变化使旧批准失效。两窗口处理同一审批只一次生效，另一个显示冲突并保留阅读上下文。

到期默认阻塞或按已定规则停止，不自动批准；拒绝反馈负责人，不允许换 Bot/账号绕过。通知仅对必须处理事项和关键变化，普通工具事件留时间线。macOS 通知展示脱敏摘要，点击回 App核对，不从通知一键执行不可逆秘密动作。

## 23. 设置、错误与真实性

设置分组：项目与资料、资源库、连接与授权、执行节点、运行环境与下载、权限与默认限制、数据与审计、App 外观与更新。按 ⌘, 复用设置窗口，错误直接定位相关对象。

每项保存说明生效范围：立即限制新动作、下个 Run、需要维护重启。语义变更需要差异确认，界面隐藏选项不是安全边界。

| 通用状态 | 反馈 |
|---|---|
| 初次加载 | 仅已知布局骨架，不预填成功记录 |
| 正常空态/搜索无结果 | 原因不同，保留筛选 |
| Core 不可用 | 缓存只读、草稿保留，危险动作禁用 |
| 状态断流 | 最后确认时间、重连/对账，不凭缓存宣称运行 |
| 权限不足 | 不泄漏隐藏对象，提供可用申请/返回路径 |
| 版本冲突 | 新版差异可见，保留未提交编辑 |
| 结果未知 | 停止自动重复外部动作，明确核验路径 |
| 费用未知 | 未提供/估算/来源报告，绝不以零替代 |
| 能力/许可不支持 | 明确技术或策略原因，不无理由灰按钮 |

收藏/筛选等展示可乐观更新；授权、取消、接管、删除、发布、验收不得提前显示成功。普通受理也不是实际执行。异常保留稳定 command_id，重复点击先查询。

## 24. Mac 体验、Electron 边界与性能

### 24.1 菜单和键盘

| 操作 | Mac 默认 |
|---|---|
| 交一件事 | ⌘N，当前窗口作用域 |
| 搜索/跳转 | ⌘K，只导航不执行高风险动作 |
| 设置 | ⌘, |
| 标准编辑 | 系统复制/粘贴/撤销/查找；不撤销外部副作用 |
| 关闭窗口 | ⌘W，不自动取消所有任务 |
| 退出 App | ⌘Q，进入停止/保存协调 |

系统菜单经 Main 实现，UI 显示 Mac 键位；快捷键处理不与按钮双提交。焦点绑定当前窗口和对象，业务弹层有可访问名称、焦点约束与关闭恢复，Esc 不批准、不取消远端任务。

### 24.2 文件、外观与可访问性

系统文件选择/保存/通知由桌面接口提供，React 业务组件不冒称 AppKit。Finder 拖放先展示资料范围/去向，可信侧校验路径/符号链接，不把页面传入路径当授权。截图使用系统字体解析，不分发字体文件。

浅/深色遵循系统或明确选择，语义 token、图标+文字表示状态。窗口缩小先收 Inspector，再收局部列表，不做手机底部导航。Retina、多显示器、系统缩放、字号放大、减少动态效果必须实测。

VoiceOver 在真实打包 Mac App测试，流式输出不逐 token朗读或抢焦点。中文输入、候选回车、多行粘贴、选中长日志、滚动保持、关键控件可达均列验收。

### 24.3 关闭、退出与重开

关全部窗口后 App仍可在 Dock 运行，只重建视图不重派任务。⌘Q显示受管理活动工作，允许取消退出或停止并保存。公共资源服务器继续在线不代表用户 Goal能在 Mac退出后继续自动调度。

Main/Core负责退出，不靠 React卸载或 beforeunload。远端无法确认停止则如实列对象，用户坚持退出保留未知，由执行侧租约安全策略处理。强退/睡眠后重新打开先核验，不能以之前 UI的“运行中”代表现在仍活跃。

### 24.4 组件与 IPC

WindowContext管视图；WorkComposer/ScopedComposer管输入；EvidenceChecklist管证据读模型；PlanRevision管版本变化；BotInbox管队列；AssetBinding/RulePreview管资源范围；ConnectionPicker/ResolvedConnection管连接摘要；AuthFlowView只显示临时官方流程；DownloadManagerView管下载阶段。

Renderer只用明确 Preload业务方法，不直接读写 SQLite、调用 shell、访问节点管理或保管秘密。Model输出不能成为具有权限的按钮脚本。多窗口共享 Core权威事实，各自游标恢复，慢视图背压、长列表虚拟化，切对象取消旧订阅，避免把旧 Bot流追加进新会话。[U1][U2]

## 25. 用户旅程

### 25.1 第一位长期 Bot

打开 App→创建开发 Bot→选目标环境→获取兼容模板→下载/验证→绑定指定连接→在该环境完成获准授权或使用 API网关→绑定项目资料/Skill/规约→第一项工作→成果验收→回到空闲→第二项关联工作使用同一身份与持久环境。

授权失效不重建 Bot，资源下载失败不清草稿，任务结束不注销登录或销毁环境；API Run级租约正常回收。用户理解自己用哪个账号、资料发向哪里。

### 25.2 目标协作与成长

用户在指挥台给暂停派工 Goal→调度 Bot安排设计/开发/评审→开发工作中可补充→独立测试发现竞态→计划版本变化→修复 C2并验证→可合并交付→确认项目经验→后续并发限制任务采用该经验。

该旅程用于验收，不是预置强制流程。简单工作直接给一个 Bot即可。内部可能用多个获准连接，系统必须给出实际连接/用量来源而不是只显示负责人账号。

### 25.3 认证失败与安全继续

任务准备中发现所选连接失效→任务和环境保留→指挥台需处理→用户在绑定环境重新授权，或明确选择获准备用连接→Core检查身份/计费/数据及旧副作用→安全边界新尝试→继续。同一个问题不需要用户反复下载文档或重新创建 Bot。

## 28. 实施顺序与设计依据

第一批以一个长期 Bot纵向切片实现 S00/S04/S05/S06/S08/S09，配最小 S15/S17/S18/S19，完成真实资料绑定、环境准备和一种获准认证路径；不要先做大市场和十种供应商。基础安全、费用不切换与秘密不泄漏是首条任务的门禁，不后补。

第二批完善 S01/S03/S07/S13 的动态目标、证据与接管，扩展受测 Runtime和远程 Provider。第三批补成熟资源管理与成长证据，P5界面随真实能力开放。所有演示数据标“演示”，不混进生产连接。

本稿是 AN交互设计。Electron框架能力参考官方 [进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)、[应用生命周期](https://www.electronjs.org/docs/latest/api/app)、[系统菜单](https://www.electronjs.org/docs/latest/api/menu)、[文件对话框](https://www.electronjs.org/docs/latest/api/dialog)、[安全](https://www.electronjs.org/docs/latest/tutorial/security)、[性能](https://www.electronjs.org/docs/latest/tutorial/performance)。厂商认证/许可参考技术稿 [第18章与参考资料](technical-design.md)。
