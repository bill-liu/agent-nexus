## 已确认的产品决定

| 范围 | 当前决定 |
|---|---|
| 产品 | Electron 桌面 App，Mac-only V1；未来再扩展其他桌面客户端 |
| 一级入口 | 任务指挥台、Bots、成长 |
| 主体 | 长期 Bot；Orchestrator 也是 Bot |
| 生命周期 | 专属逻辑 Sandbox 跟 Bot，任务完成不销毁；进程可恢复/重启 |
| 执行 | Codex/Cursor/Claude Code CLI 全在 Sandbox；本地、远程统一协议 |
| 配套服务 | Resource Server 管模板、基础环境、版本和下载；不自动迁移私有数据/调度 |
| 用户资产 | 知识、Skill、规约、经验本地优先；授权、版本和采用可追溯 |
| 连接选择 | 用户决定账号/计费来源；Bot 默认连接可受控覆盖 |
| 认证解析 | ConnectionResolver 确定性检查实际认证、数据和兼容性 |
| 默认故障策略 | 不自动订阅→API，不绕过网关，不借用其他账号 |
| 成长 | 有来源、可撤回、可评测；RRSI/决策模型不改权限或付款来源 |

React、Core Worker、SQLite、VM/helper、Bubblewrap 与各 Provider 的具体库版本、接口及部署细节是需要 P0/P1 验证的实现建议，不是已实现能力。单权威 Core 与 Renderer 无权限等边界不得因技术替换丢失。

## 相比 v1.2 的关键修订

- 取消“独立服务端一律不做”的过度约束，增加公共资源服务与制品分发，保留本地权威 Core。
- 补齐 AssetRegistry/ContextAssembler：资料、Skill、规约、经验的归属、装载、撤回及数据处理政策。
- 补齐 ConnectionRegistry、ConnectionGrant、ConnectionResolver、RuntimeAuthAdapter 与凭据生命周期。
- 区分认证方式、计费来源、请求路径；启动前验证实际生效方式，清理相冲突的继承配置。
- 增加连接、官方授权、下载、资产管理、运行快照及错误/费用提示页面。
- 第三方 CLI 的认证和分发许可须独立核验。尤其不能把“官方 Claude Code 装在 Sandbox”视为 AN 可向产品用户提供订阅登录的充分授权；受限制路径默认阻塞，详情见技术稿第18章。
- 保留旧规格核心验收标识并增加资源/认证场景；这些都是待执行测试，不能宣称已经通过。
