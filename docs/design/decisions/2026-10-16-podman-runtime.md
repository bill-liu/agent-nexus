# ADR：采用 Podman 作为 AN 默认本地执行后端

**状态：用户已确认选型；迁移尚未实现或验收。**  
**日期：2026-10-16。**  
**读取基点：`c12d012c1195835bbc6d1c0f7c24883582a622ce`。**

用户决定：“就使用 podman 吧，不重复建设了，而且简单高效。”本记录把这一决定落到执行边界；“简单高效”是设计目标，不是已测性能结论。本次仅修改设计与阅读入口，没有安装软件、启动 VM/容器、登录账号、调用模型、修改业务代码或重新执行产品测试。

## 1. 决策与优先级

AN 采用 **Podman CLI + Podman Machine + OCI Bot 镜像 + 持久工作数据** 作为默认 Mac 本地执行路线。Podman Desktop 不是前置要求。不再并行建设自研 VM 平台、Lima 后端或类 Docker 的原生软件包管理系统作为首发必需品。

Bot 是长期智能执行实体；逻辑环境有稳定身份、工作目录、配置、会话和任务归属。它不等于一台 VM，也不要求某个 CLI 进程永不退出。隔离是执行后端提供的能力，AN 的核心是持续接单、执行、交互、验收和经验沉淀。

本 ADR 在执行后端、首次安装和相关前置条件上，优先于 v1.3 技术设计 §07/08/24/25、旧 P1 计划及 Ubuntu/helper 首装配方的冲突表述。其他产品、Connection、权限、证据与持久化要求继续适用。原生受管执行是已讨论但本轮未选的路线，不再作为默认迁移目标；远程 Sandbox 保留为之后的独立适配。

旧代码和报告保留；不得把“选用 Podman”改写成已完成迁移，也不得把旧后端的测试结果直接标成 Podman PASS。

## 2. 最小架构

```text
AN Desktop / 单一 Core / SQLite
            │
     PodmanProvider + RunnerClient
            │
    一套经授权选定的 Podman Machine
            │
      共享、固定摘要的 OCI 镜像
       ┌────┼────┐
       ▼    ▼    ▼
     Bot A Bot B Bot C 的容器
     各自工作卷、配置、会话及凭据范围
       │
     AN Runner → 首个 Codex CLI
```

Podman 在 Mac 上仍使用 Linux VM，但其机器镜像和生命周期交给 Podman，不再要求用户提供外部 ARM64 制备机。首个验收只跑一个 Bot；共享同一引擎不等于需要同时启动所有 Bot，也不等于全部进程只占一份内存。[P1][P2]

AN 保留 Bot/Inbox/Goal、单一 Core、Connection、审批、资产、Runner 协议和独立验收。Provider 只封装经过验证的引擎操作；不复制 OCI 镜像层、容器生命周期、虚拟化或通用包管理实现。

## 3. 环境交付与持久化

- **机器层：**使用固定受测版本的 Podman 及官方支持的 Machine 镜像。显式选定 machine/connection；不偷偷切换用户全局默认连接、不覆盖既有安装或停止无关容器。安装、机器资源和镜像下载仍需对应授权。
- **镜像层：**一个最小 Codex/Runner 工具镜像，版本和 digest 固定。优先复用现成 OCI Registry，Resource Server 提供目录/兼容信息；不另建镜像仓库协议。第三方 CLI 的安装与再分发条件单独核验；公共镜像不包含用户秘密或项目数据。
- **Bot 层：**每个 Bot 有自己的容器绑定、持久工作卷/目录、配置与会话范围。基础工具只需拉取一次供同一引擎复用；项目依赖按项目和锁文件准备。新工具变更进入版本化镜像或明确私有扩展，不修改其他 Bot 的环境。
- **生命周期：**任务完成不删除容器或数据。短期可保留 Runner，较长空闲可在安全边界停止容器；停止不等于清数据。升级采用排空、校验、受控重建并重新挂载工作数据，不覆盖活动 Run。
- **卷与备份：**业务持久数据不得只依赖容器可写层。明确卷实际位于 Machine 内还是宿主授权目录；Machine 删除/重置可能破坏其内部卷，卷不是备份。普通备份排除认证资料，敏感备份另行授权。[P4]

设计“一台 Machine 多 Bot”而不是“一 Bot 一台完整 VM”。但部署前还须核验与用户已有 Podman 的共存：当前官方 machine-start 文档限制同一时刻一个 Podman 管理 VM 活动；遇已有活动机器应展示冲突并让用户选择复用或稍后处理，不能自动停止它。按安装版本重新核验，不承诺双 Machine 同时运行。[P3]

## 4. 保护、认证与运行事实

优先使用 Podman 的非特权/rootless 执行与已验证的 Runtime 配置，不默认叠加自研 Bubblewrap/cgroup/BPF 层。需要的保护以实际能力声明与正反例证明，不能把删除旧实现视为通过所有旧安全门禁。[P5]

至少保留以下边界：

- 挂载只覆盖获准资料与当前 Bot 工作数据；检查 Machine 的默认宿主共享和容器挂载两个层次，不把默认 Home 共享当作用户授权。[P2]
- Bot 容器不得得到 Podman socket、机器管理密钥、Core 数据库、其他 Bot 的工作卷或整份宿主 Home。引擎管理通路只由受信任控制侧掌握。
- 不以 `--privileged`、额外宽权限、全部关闭 Runtime 保护等方式静默解决嵌套兼容问题。先固定一个实际兼容的 Codex 配置，能力不足则阻塞对应任务并说明原因。
- 用户仍选择具名 Connection 与计费来源；软件镜像准备就绪不等于账号已授权。官方登录按实际容器内 CLI 流程完成，登录态按 Bot 范围保留，不每任务重登、不拷贝整份宿主认证缓存。不静默订阅转 API，不绕过网关。
- Podman 网络开关不自动提供域名/逐请求级授权；local-only 和网关要求必须映射到实际执行点。无法达到当前任务必需限制时阻塞，不展示假保证。
- Runner 常驻意味着**容器运行状态不是单个 Run 状态**。复用单写槽位、命令去重、原生审批和结果证据；子进程尚可能写入时不能释放槽位。无法确认本 Run 已停可停止仅属于该 Bot 的容器并对账，但不能停止其他 Bot 或共享机器来冒充精确取消。
- rootless、非 root 容器用户、Runtime 内部沙箱是不同层次，不互相冒充。权限和资源限制必须针对受测版本验证，不能仅依据配置字段就宣称生效。

## 5. 复用与停止重复建设

| 范围 | 处理 |
|---|---|
| Core、Inbox、SQLite、Connection、审批、资料、独立验收 | 继续复用，不创建第二套控制系统 |
| Runner/CLI 适配、回执、流式事件、Task A/B | 保留通用契约，替换具体启动、通信和执行观察适配 |
| 自研 Swift VM helper、Ubuntu raw/EFI/chroot 制备、外部 ARM64 制备机要求 | 不再扩展为默认路径；保留旧代码/证据，等 Podman 路径验收后再讨论清理 |
| guest Node 中的通用协议与错误处理 | 按需复用；不为复用旧代码重新装一套管理操作系统或特权服务 |
| 自研 cgroup/BPF/vsock 管理链 | 优先由引擎能力替代；逐项重新映射所需保证，不整体宣布等价 |
| Mac 原生验证器及 Mac App 构建 | 与 VM helper 分开处理，不因取消自研 VM 而删除；Linux 容器不能替代 macOS/Xcode 验证 |
| 远程 Sandbox、决策模型 Issue #2 | 仍为之后能力，不加入本次首个本地闭环前置 |

## 6. 接手时的最小顺序

1. 读取最新 main、本 ADR、当前 P1 报告和运行接口。给出小范围迁移映射及可验证切片，不重新编写总体架构，不同时接入所有 CLI/云厂商。
2. 建立 PodmanProvider：固定版本、明确 engine connection、检测/准备/拉取/创建/启动/连接/停止/检查。已有对象采用身份与标签核对，重复请求不重复创建；引擎失联先对账。
3. 建一个最小 OCI 环境与独立工作卷，接上现有 Runner/Codex，先以无账号合成任务检验通信、重启、持久化和停止。
4. 在获准 Mac 上测首次准备、镜像复用、容器启动、空闲/工作峰值和关闭后的占用；不沿用旧 4 GiB VM 或 50–70 GiB 制备估算作为新方案指标。
5. 具名 Connection、数据与费用授权齐备后，执行原 Task A/B，独立验证同一 Bot 保留 A 的工作结果继续 B；验证审批/拒绝、取消、恢复、版本固定和备份。

验收最少要证明：无外部制备机的受监督首装；同版本镜像复用；任务结束不清数据；第二 Bot 不共享第一 Bot 私有写目录；旧进程/未知状态不产生双写；不影响用户其他容器；账号和费用不静默切换；更新不覆盖活动成果。具体适配代码和自动化测试须另有实现提交，本 ADR 未执行这些测试。

“准备本地环境”向用户展示下载、资源预算、来源和进度；日常只管理 Bot，不要求打开 Podman Desktop 或输入容器命令。这是待实现体验，不是承诺当前 App 已自动安装完成。首次真实安装、设备接入、模型账号/付费和公共镜像发布仍使用相应授权；选型确认不是无限制设备授权。
