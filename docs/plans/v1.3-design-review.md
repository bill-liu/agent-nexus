## 1. 阅读结论

AN 是 Mac-only V1 的 Electron 桌面产品。任务指挥台、Bots、成长是三个主入口；资源、连接、下载、生效快照服务于这些入口，不扩张成新的一级产品。一个长期 Bot 有稳定身份、独占写槽位和持久逻辑 Sandbox；Task 结束保留环境，App 重开先对账。Conversation、Task、Run、RuntimeSession/Turn 分开建模。

本地 Core 是任务、权限和状态的唯一权威，SQLite 和本地文件保存私有数据。Renderer 只展示并发出有类型命令，Main 管窗口、菜单、文件和秘密桥接，Core Worker 执行业务。多窗口、第二 App 实例、React 重挂载都不能产生第二次调度。云端开发、云端 macOS 编译是开发方式，**不改变产品本地 Core 的部署决策**。

Mac 上的 CLI 在受管 Linux VM 内的 Bot Sandbox 中运行；Electron 的 Renderer sandbox 不替代它。Provider 管环境，RunnerClient 管执行，Driver 适配实际 CLI 协议。远程节点是受授权的执行位置，不能拥有另一套权威 Core，也不能用“断线即重试”制造双写。进程、内存和 socket 不承诺跨停机保活；目录、未提交变更、业务身份和可恢复引用需要保留。

Task、Inbox、Outbox 原子提交，Runner 先持久化命令再 ACK。整体是至少一次投递和幂等处理；未知外部副作用不能当作从未执行。租约过期与 fencing token 只能约束协议写入，还要证明旧 CLI 已退出或被隔离，才能释放同一工作区的写权。

Connection 将认证、账单、账号、路由和数据策略分离。Task 可以显式覆盖 Bot 默认连接，但必须经过授权与兼容检查；不能因订阅失效切到 API、网关失败切直连，或借用别的 Bot 认证目录。实际来源不可观测就标明声明/未知，无法满足约束则阻塞。

知识、Skill、规约和经验是有版本、有授权、有来源的资产。ContextAssembler 固定运行快照；local-only 同时约束检索、Embedding、摘要、工具及最终模型。Skill 安装、启用、授权分开，脚本仅在 Sandbox 执行。撤回阻止后续使用并列出影响，不能承诺模型忘记已读内容。

Resource Server 只承载公共目录、模板版本、下载授权与分发；不存私有任务、资料和用户认证，不做私有调度云，也不是模型网关。包必须验证来源、签名、digest、目标架构和安全解包；缓存可用不等于绕过首次信任。公共服务断线不删除已装 Bot。

最终 V1 是 P0–P4：单 Bot 基础、扩展运行时/节点、有界 Orchestrator 调度三个长期专业 Bot、证据驱动重规划及后续经验复用。P0/P1 先交付真实单 Bot 纵向切片；不把多 Bot 调度、学习或 P5 优化画成已实现能力。候选代码、验收合同、包与独立证据必须对应同一版本；“可合并”不等于已推送、已合并或已发布。

## 4. 认证与工具官方核验

核验日期为 2026-10-12；发布/真实认证前须按当时页面和实际版本重核。以下为能力与适用条件记录，不构成 AN 已获认证集成许可。

- Codex 的 [App Server / Auth endpoints](https://learn.chatgpt.com/docs/app-server#auth-endpoints) 区分本地/开源应用与商业或托管服务，并指出 app-server authentication 不适用于后者。AN 需分别评估本地个人验证、本地开源发行、商业/托管形态；“开源仓库”或远程节点技术跑通都不能替代适用性证据。[Sign in with ChatGPT](https://developers.openai.com/siwc) 仅为待审核候选，当前无 client ID 或自建 token 刷新代理授权。P1 不能用自动改 API 计费回避限制。
- [Codex authentication](https://learn.chatgpt.com/docs/auth) 说明官方浏览器/设备登录及 API 路径；设备登录还可能受账号/工作区设置限制。计划不自动改设置、不拷贝宿主认证缓存。能查询登录状态不代表已验证具体集成方式、账单来源和数据去向。
- [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance) 对产品中运行未修改官方二进制及终端用户通过官方流程使用自身订阅列出适用条件；这与 AN 自行提供 Claude.ai 登录、收集/代理订阅凭据不同。不能简化成“第三方沙箱一律禁用订阅”，也不能由托管二进制推导可自建认证。P2 集成前记录产品形态、条款时间、官方流程、直接付费主体和具体账号路径；未知仍默认 POLICY_RESTRICTED，不靠用户风险确认绕过。
- [Electron security](https://www.electronjs.org/docs/latest/tutorial/security) 支持分离上下文、受限桥接和校验 IPC 来源；这些机制不自动实现业务授权。[utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process) 是 Core 容器候选，默认继承环境需改成显式白名单；它不是 Bot 执行沙箱。
- [SQLite transactions](https://sqlite.org/lang_transaction.html) 的单写者约束与本地 Core 匹配；短事务中不等待网络，不照搬 PostgreSQL 的 SKIP LOCKED。

Runtime/Auth preflight 记录至少包括：场景及适用范围、证据 URL/核验时间、CLI/协议精确版本、配置摘要、环境变量名称白名单、目标节点/generation、实际认证来源、endpoint/路由、账号及 billing evidence 等级、数据政策、Grant revision、缓存保存位置与隔离方式、长进程换凭据机制、检查结论和失效条件。不得保存 token、设备码、原 Key 或完整认证响应。配置、版本、路由、Grant 或账号变化使旧结论失效。首个真实调用前再次检查。
